# Migrating from database-sqlite → database-postgres

Single-machine move from the default SQLite store to Postgres. No cloud services required.

## Prerequisites

- Docker or a local Postgres 16+ listening on `localhost:5432`
- MuxCore stack already running with `database-sqlite` (installer / `_mvp`)
- `database-postgres` implements `Backupable` via `pg_dump` plain SQL (or an internal SQL dump when `pg_dump` is absent)

## Dialect checklist (SQLite SQL → Postgres)

Callers and one-shot dumps must adapt SQL written for SQLite:

| SQLite | Postgres |
|--------|----------|
| `?` placeholders | `$1`, `$2`, … (pgx / DatabaseService args stay positional) |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGSERIAL PRIMARY KEY` or `GENERATED BY DEFAULT AS IDENTITY` |
| `AUTOINCREMENT` | `SERIAL` / `IDENTITY` — no AUTOINCREMENT keyword |
| `DATETIME` / `datetime('now')` | `TIMESTAMPTZ` / `NOW()` |
| `INTEGER` for booleans | `BOOLEAN` (`TRUE`/`FALSE`) |
| `BLOB` | `BYTEA` |
| `IF NOT EXISTS` DDL in migrations | Supported; prefer idempotent Up SQL in both dialects when modules must run on either backend during transition |
| Double-quoted identifiers | Same; unquoted names fold to lower case in Postgres |
| `PRAGMA …` | No equivalent — use session settings (`SET search_path`, etc.) |
| `_migrations` in default schema | Set `PGSCHEMA` per sidecar when sharing one cluster |

Modules should emit Postgres SQL when `database-postgres` is selected (capability `database.postgres`). During migration, grep dumps for `?`, `AUTOINCREMENT`, and `datetime(` before piping to `psql`.

## 1. Start Postgres

```bash
docker run --rm -d --name muxcore-pg \
  -e POSTGRES_USER=muxcore \
  -e POSTGRES_PASSWORD=muxcore \
  -e POSTGRES_DB=muxcore \
  -p 5432:5432 \
  postgres:16-alpine
```

Or reuse CI-style env:

```bash
export PGHOST=localhost PGPORT=5432 PGUSER=muxcore PGPASSWORD=muxcore PGDATABASE=muxcore PGSSLMODE=disable
```

## 2. Snapshot SQLite (optional but recommended)

With `backup-local` registered and both modules implementing `Backupable`:

```bash
# CreateBackup including module id database-sqlite (see backup-local README grpcurl examples)
```

Also copy the file as a cold backup:

```bash
cp "$MUXCORE_DATA/sqlite/muxcore.db" "$MUXCORE_DATA/sqlite/muxcore.db.bak"
```

`database-postgres` `ExportState`/`ImportState` round-trip via `pg_dump`/`psql` when client tools are on PATH.

## 3. Swap the module

Stop `database-sqlite`. Start `database-postgres` with the same mesh settings the installer uses for other sidecars, plus:

| Variable | Example |
|----------|---------|
| `MUXCORE_MODULE_ID` | `database-postgres` |
| `DATABASE_GRPC_ADDR` | `127.0.0.1:9701` |
| `PGHOST` / `PGPORT` / `PGUSER` / `PGPASSWORD` / `PGDATABASE` | as above |
| `PGSCHEMA` | `public` (or per-module schema on shared clusters) |
| or `DATABASE_URL` | `postgres://muxcore:muxcore@127.0.0.1:5432/muxcore?sslmode=disable` |

Do **not** run both providers at once — they both advertise capability `database`.

## 4. Re-apply schema / data

- Modules that call `Migrate` on startup will recreate their tables against Postgres.
- For existing SQLite rows, use a one-shot dump:

```bash
sqlite3 "$MUXCORE_DATA/sqlite/muxcore.db" .dump > /tmp/muxcore-sqlite.sql
# Apply dialect checklist, then:
psql "$DATABASE_URL" -f /tmp/muxcore-adapted.sql
```

Prefer re-seeding from fixture/smoke paths on a laptop demo rather than perfect SQL translation.

## 5. Verify

```bash
cd database-postgres && nix-shell -p go postgresql --run 'go test -count=1 ./...'
../_mvp/scripts/exercise-postgres-path.sh
```

**Vault lab:** live Postgres on vault — `nix-shell -p go postgresql --run 'cd database-postgres && PGHOST=/run/postgresql PGUSER=postgres PGDATABASE=muxcore_pg_exercise PGSSLMODE=disable go test ./...'`.

Confirm admin-ui / API still resolve capability `database`, then remove the SQLite process from `up.sh` / installer essentials when satisfied.

## Installer note

Default installer profile stays on `database-sqlite`. Optional:

```bash
export MUXCORE_PROFILE=postgres
# or set DATABASE_URL / PG* yourself
./up.sh
```

The installer starts `database-postgres` and, when `DATABASE_URL`/`PGHOST` are unset, a local Docker `postgres:16-alpine` (lab credentials `muxcore`/`muxcore`). Docker is required only when you do not already have Postgres.
